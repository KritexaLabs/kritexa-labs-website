**Notes:**
1. `aspect-ratio` — supported in Safari 15+. All current Safari versions (15+) are supported.
2. `backdrop-filter` — supported in Firefox 103+. Firefox 154 fully supports it.
3. `backdrop-filter` with `-webkit-` prefix — required for Safari; all instances now have both prefixed and unprefixed declarations.
4. `100vh` / `position: fixed` / `position: sticky` — Safari on iOS has historically had dynamic viewport height issues. All elements using `100vh` are hero sections where minor viewport unit discrepancy is non-critical. No functional defect.
5. `display: contents` — used in footer responsive stacking (`f-right-stack`). Known to have issues in very old Safari (< 14) for elements with `order`. Safari 14+ handles correctly; older versions show items in DOM order without visual regression.
6. `scrollbar-width`/`scrollbar-color` — **FIXED in Phase 19**: added to `css/global.css` for Firefox styled scrollbar support.
7. Canvas 2D — BUSINESS canvas only on home page; protected by reduced-motion guard and element guards on all other pages.
8. `CanvasRenderingContext2D.roundRect` — added in Chrome 99+, Firefox 112+, Safari 16+. Code uses `if(oCtx.roundRect)` guard with `oCtx.rect()` fallback. Fully compatible.

### Browser-Specific CSS Notes

**Firefox:**
- `backdrop-filter` transitions not animated (jumps on state change). This is an expected browser-native behavior difference — Firefox does not animate `backdrop-filter`. Visual impact is minimal; navbar frosted glass appears instantly rather than fading. **CLASSIFIED: B3 — Minor rendering difference. No fix applied.**
- Scrollbar: Previously showed default Firefox scrollbar (no custom styling). **FIXED in Phase 19** by adding `scrollbar-width: thin; scrollbar-color` to `css/global.css`.
- Form controls: Firefox renders select elements and inputs with slightly different default styling. `-webkit-appearance: none` is applied only to form inputs (not select) in components.css. This is standards-compliant behavior.

**Edge (Chromium 151):**
- Identical to Chrome behavior (same Blink engine version).

**Safari (STATICALLY VERIFIED — no runtime testing):**
- `-webkit-backdrop-filter` prefix required and now present on all instances.
- Dynamic viewport height (`100svh`/`dvh`) not used; `100vh` used only in hero sections where the discrepancy is cosmetic.
- `display: contents` ordering — Safari 14+ handles correctly.
- Form control appearance differs (native iOS styling). `-webkit-appearance: none` applied to text inputs.
